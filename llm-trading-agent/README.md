# LLM Trading Agent (페이퍼 트레이딩 실험)

LLM이 투자 판단을 내리는 **과정**을 기록하고, 그 기록이 비용·세금·슬리피지를 반영한 뒤에도 벤치마크와 비교할 의미가 있는지 사후에 살펴보기 위한 실험 디렉터리입니다. BenchmarkAI, AI Stock Challenge 같은 LLM 투자 대회의 형식(분석, 의사결정, 성적 기록)만 참고합니다. 대회 성적을 재현하거나 초과 수익을 목표로 두지 않습니다.

이 디렉터리는 Investment OS 본체와 분리되어 있습니다. 서버, 주문, 계좌, API 키에 연결하지 않습니다.

## 경고

- **대회·리더보드 성적은 실계좌 기댓값이 아닙니다.** 공개 순위는 대개 매매 비용, 세금, 슬리피지를 빼지 않습니다. 기간이 짧고, 체결은 가상입니다. 같은 매매를 비용까지 넣어 다시 계산하면 성적은 크게 낮아지는 것이 정상입니다.
- **현실에서 기대할 수익은 그보다 훨씬 낮아야 합니다.** 짧은 구간의 수익률, 샤프, 승률은 운과 과최적화로도 쉽게 나옵니다. 이 실험의 숫자는 가설을 기록하기 위한 것이며 미래 수익의 예고가 아닙니다.
- **투자 자문이 아닙니다.** 특정 종목의 매수·매도를 권하지 않습니다. 모델이 쓴 문장은 검토용 초안입니다.
- **주문을 자동 실행하지 않습니다.** 브로커 연동, 주문 API, 계좌 자격 증명, 실주문 코드를 두지 않습니다. 출력의 `autoExecute`는 항상 `false`이고 `broker`와 `order`는 항상 `null`입니다. 사람이 따로 증권 화면을 열더라도, 이 저장소의 코드가 그 주문을 보내서는 안 됩니다.
- **페이퍼 트레이딩만 합니다.** 체결가는 가정입니다. 체결 규칙, 비용표, 벤치마크, 한도는 평가를 시작하기 전에 고정합니다.

## 파이프라인

판단은 한 역할이 끝내지 않습니다. 뒤 역할은 앞 역할이 남긴 기록만 입력으로 받습니다.

1. **분석** (`prompts/analysis.md`)  
   사실과 추정을 나눕니다. 사실에는 출처와 기준 시각이 있습니다. 상승·기준·하락 시나리오와, 눈으로 확인할 수 있는 무효화 조건을 적습니다. 매매 의견은 내지 않습니다.
2. **의사결정** (`prompts/decision.md`)  
   분석 메모만 보고 `BUY` / `SELL` / `HOLD` / `WAIT` 중 하나를 고릅니다. 증거가 약하면 `WAIT`가 기본값입니다. 비중 변화는 제안이지 주문이 아닙니다.
3. **리스크** (`prompts/risk.md`)  
   비중, 1회 크기, 낙폭 중단, 현금 하한, 집중도, 유동성을 검사하고 레버리지와 공매도를 거부합니다. 한도를 넘기면 크기를 줄이거나 **거부(veto)** 합니다. 의사결정 역할은 이 판정을 뒤집지 못합니다.

승인과 축소, 거부는 모두 페이퍼 로그에 남깁니다. 거부는 체결로 집계하지 않습니다. 로그를 어떻게 채점할지는 `evaluation.md`에 있습니다.

```
사실·시세·공시 (기준 시각 고정, 운영자가 제공)
        │
        ▼
  analysis   사실 / 추정 / 시나리오 / 무효화
             매매 의견 없음
        │
        ▼
  decision   BUY · SELL · HOLD · WAIT
             증거가 약하면 WAIT
        │
        ▼
  risk       APPROVE · REDUCE · VETO
        │
        ▼
  사람이 읽는 페이퍼 로그
  주문 실행 없음
```

## 디렉터리

| 경로 | 내용 |
| --- | --- |
| `README.md` | 목적, 경고, 파이프라인 |
| `prompts/analysis.md` | 분석 역할 프롬프트 |
| `prompts/decision.md` | 의사결정 역할 프롬프트와 JSON 스키마 |
| `prompts/risk.md` | 리스크 역할 프롬프트, 예시 한도, 거부 규칙 |
| `evaluation.md` | 성과 지표, 최소 평가 기간, 과최적화·사전관측 방지 |
| `src/types.ts` | 위 입출력의 TypeScript 형태. 런타임 주문 로직 없음 |

프롬프트 본문을 바꾸면 해당 `schemaVersion`을 올리고 새 `experimentId`로 트랙을 시작합니다. 같은 트랙 안에서 문장이나 한도를 고치면 결과를 본 뒤의 수정이 됩니다. 봉인 규칙은 `evaluation.md`를 따릅니다.

## Investment OS와의 관계

본체의 운용 원칙과 같습니다. 이 저장소는 판단을 돕고 기록을 남기며, 증권사 API로 주문을 넣지 않습니다. 레짐, 캡처 검수, 게이트키퍼 등 기존 기능은 이 실험에 연결되어 있지 않습니다. `src/types.ts`는 앱 엔트리에서 import하지 않습니다.
